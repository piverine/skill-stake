# Requirements Document

## Introduction

Skill-Stake is a blockchain-based learning verification platform that incentivizes serious study by requiring users to stake ETH before taking AI-generated quizzes. Users upload study materials (PDFs), stake cryptocurrency, and must achieve a 70% score to recover their stake - otherwise it goes to charity. The system combines secure authentication, AI-powered quiz generation, and smart contract automation to create accountability in learning.

## Glossary

- **Skill_Stake_System**: The complete platform including frontend, backend, database, and smart contracts
- **User**: An authenticated individual who stakes ETH and takes quizzes
- **Study_Material**: PDF documents uploaded by users for quiz generation
- **Quiz**: A 10-question assessment generated by AI from study materials
- **Stake**: ETH deposited by users as collateral for quiz attempts
- **Smart_Contract**: Ethereum contract that holds stakes and executes payouts
- **AI_Engine**: Gemini 3 Flash API service that processes PDFs and generates quizzes
- **Authentication_Service**: Clerk-based secure login system
- **Database**: NeonDB instance storing user data, quiz history, and stake status

## Requirements

### Requirement 1: User Authentication and Security

**User Story:** As a user, I want to securely authenticate and access only my own stakes and quiz data, so that my learning progress and financial stakes remain private and protected.

#### Acceptance Criteria

1. WHEN a user attempts to access the platform, THE Authentication_Service SHALL require valid Clerk authentication
2. WHEN a user is authenticated, THE Skill_Stake_System SHALL provide JWT tokens for secure API access
3. WHEN accessing stake or quiz data, THE Skill_Stake_System SHALL verify JWT tokens and ensure users can only access their own data
4. WHEN authentication fails, THE Skill_Stake_System SHALL deny access and return appropriate error messages

### Requirement 2: Study Material Upload and Processing

**User Story:** As a user, I want to upload PDF study materials, so that the AI can generate relevant quizzes for my learning verification.

#### Acceptance Criteria

1. WHEN a user uploads a PDF file, THE Skill_Stake_System SHALL validate the file format and size limits
2. WHEN a valid PDF is uploaded, THE AI_Engine SHALL process the document and extract text content
3. WHEN PDF processing is complete, THE AI_Engine SHALL generate exactly 10 quiz questions in structured JSON format
4. WHEN quiz generation fails, THE Skill_Stake_System SHALL notify the user and allow re-upload
5. THE AI_Engine SHALL validate generated quiz data against Pydantic schemas before storage

### Requirement 3: ETH Staking and Smart Contract Integration

**User Story:** As a user, I want to stake ETH on Sepolia testnet before taking quizzes, so that I have financial incentive to study seriously and perform well.

#### Acceptance Criteria

1. WHEN a user initiates staking, THE Smart_Contract SHALL accept ETH deposits on Sepolia network
2. WHEN ETH is staked, THE Database SHALL record the stake amount, user ID, and timestamp
3. WHEN a stake is recorded, THE Skill_Stake_System SHALL prevent quiz access until staking is confirmed
4. THE Smart_Contract SHALL hold staked ETH in escrow until quiz completion and scoring

### Requirement 4: Quiz Generation and Validation

**User Story:** As a user, I want AI-generated quizzes that accurately test my understanding of uploaded materials, so that the assessment is fair and relevant to my study content.

#### Acceptance Criteria

1. WHEN generating quizzes, THE AI_Engine SHALL create exactly 10 questions based on PDF content
2. WHEN questions are generated, THE AI_Engine SHALL return structured JSON with questions, multiple choice options, and correct answers
3. WHEN quiz data is received, THE Skill_Stake_System SHALL validate the JSON structure using Pydantic schemas
4. WHEN validation passes, THE Database SHALL store the quiz data linked to the user's stake record

### Requirement 5: Quiz Taking and Scoring

**User Story:** As a user, I want to take quizzes through an intuitive interface and receive immediate scoring, so that I can verify my learning and know the outcome of my stake.

#### Acceptance Criteria

1. WHEN a user accesses a quiz, THE Skill_Stake_System SHALL display questions one at a time or all together based on UI design
2. WHEN a user submits answers, THE Skill_Stake_System SHALL calculate the score as a percentage of correct answers
3. WHEN scoring is complete, THE Skill_Stake_System SHALL immediately display the results to the user
4. THE Skill_Stake_System SHALL store quiz results and timestamps in the Database

### Requirement 6: Smart Contract Settlement and Payout

**User Story:** As a user, I want automatic payout of my stake when I score 70% or higher, and transparent charity donation when I score below 70%, so that the incentive system is fair and automated.

#### Acceptance Criteria

1. WHEN a quiz score is 70% or higher, THE Skill_Stake_System SHALL trigger the Smart_Contract to release staked ETH to the user
2. WHEN a quiz score is below 70%, THE Smart_Contract SHALL automatically transfer staked ETH to a verified charity address
3. WHEN settlement occurs, THE Database SHALL update the stake status to "settled" with payout details
4. WHEN settlement fails, THE Skill_Stake_System SHALL log errors and allow manual resolution

### Requirement 7: Data Persistence and Retrieval

**User Story:** As a user, I want my quiz history, stake records, and profile data to be reliably stored and quickly accessible, so that I can track my learning progress over time.

#### Acceptance Criteria

1. THE Database SHALL store user profiles, quiz history, stake records, and settlement status
2. WHEN users request their data, THE Database SHALL return results within acceptable response times
3. WHEN data is stored, THE Database SHALL ensure ACID compliance for financial stake records
4. THE Database SHALL maintain referential integrity between users, stakes, quizzes, and settlements

### Requirement 8: System Integration and API Design

**User Story:** As a system architect, I want clean separation between frontend, backend, AI services, and blockchain components, so that the system is maintainable and each component can be updated independently.

#### Acceptance Criteria

1. WHEN frontend requests are made, THE Backend SHALL provide RESTful API endpoints for all user operations
2. WHEN AI processing is needed, THE Backend SHALL interface with Gemini API using proper error handling
3. WHEN blockchain operations are required, THE Backend SHALL interact with Smart_Contract through web3 libraries
4. THE Backend SHALL validate all inputs using Pydantic models before processing or storage
